Portals can be installed in multiple ways:

* [**Portals Desktop (Recommended)**](#install-and-run-portals-desktop): Download and install the standalone desktop application for the least complicated setup experience.
This option includes dependency management and facilitated upgrades.

* [**Docker**](#install-and-run-portals-docker): Pull and run the Portals Docker image to start a Portals container and run Portals in isolation.

* [**Python package**](#install-and-run-the-portals-oss-python-package): Install and run the Portals OSS Python package.
This option offers more control over the environment, dependencies, and versioning.

* [**Install from source**](/contributing-how-to-contribute#install-portals-from-source): Use this option if you want to contribute to the Portals codebase or documentation.

## Install and run Portals Desktop

Portals Desktop is a desktop version of Portals that simplifies dependency management and upgrades.
However, some features aren't available for Portals Desktop, such as the **Shareable Playground** and **Voice Mode**.

<Tabs>
<TabItem value="macos" label="macOS" default>

Portals Desktop requires macOS 13 or later.

1. Navigate to [Portals Desktop](https://www.portals.org/desktop).
2. Click **Download Portals**, enter your contact information, and then click **Download**.
3. Mount and install the Portals application.
4. When the installation completes, open the Portals application, and then create your first flow with the [Quickstart](/get-started-quickstart).

</TabItem>
<TabItem value="Windows" label="Windows">

    :::warning
    If you are upgrading Portals Desktop on Windows, **don't** use the in-app update feature to upgrade to Portals version 1.6.0.
    For more information, see [Known issues for 1.6.0](/release-notes#windows-desktop-update-issue).
    :::

1. Navigate to [Portals Desktop](https://www.portals.org/desktop).
2. Click **Download Portals**, enter your contact information, and then click **Download**.
3. Open the **File Explorer**, and then navigate to **Downloads**.
4. Double-click the downloaded `.msi` file, and then use the install wizard to install Portals Desktop.

    :::tip
    Windows installations of Portals Desktop require a C++ compiler that may not be present on your system. If you receive a `C++ Build Tools Required!` error, follow the on-screen prompt to install Microsoft C++ Build Tools, or [install Microsoft Visual Studio](https://visualstudio.microsoft.com/downloads/).
    :::

5. When the installation completes, open the Portals application, and then create your first flow with the [Quickstart](/get-started-quickstart).

</TabItem>
</Tabs>

For upgrade information, see the [Release notes](/release-notes).

To manage dependencies in Portals Desktop, see [Install custom dependencies in Portals Desktop](/install-custom-dependencies#portals-desktop).

## Install and run Portals with Docker {#install-and-run-portals-docker}

You can use the Portals Docker image to start a Portals container.
For more information, see [Deploy Portals on Docker](/deployment-docker).

1. Install and start [Docker](https://docs.docker.com/).

2. Pull the latest [Portals Docker image](https://hub.docker.com/r/portalsai/portals) and start it:

    ```bash
    docker run -p 7860:7860 portalsai/portals:latest
    ```

3. To access Portals, navigate to `http://localhost:7860/`.

4. Create your first flow with the [Quickstart](/get-started-quickstart).

## Install and run the Portals OSS Python package

1. Make sure you have the required dependencies and infrastructure:

    - [Python](https://www.python.org/downloads/release/python-3100/)
       - macOS and Linux: Version 3.10 to 3.13
       - Windows: Version 3.10 to 3.12
    - [uv](https://docs.astral.sh/uv/getting-started/installation/)
    - Sufficient infrastructure:
       - Minimum: Dual-core CPU and 2 GB RAM
       - Recommended: Multi-core CPU and at least 4 GB RAM
    - Browser:
       - Google Chrome is recommended but not required

2. Create a virtual environment with [uv](https://docs.astral.sh/uv/pip/environments).

    <details>
    <summary>Need help with virtual environments?</summary>

    Virtual environments ensure Portals is installed in an isolated, fresh environment.
    To create a new virtual environment, do the following.

        <Tabs>
        <TabItem value="linux-macos" label="Linux or macOS" default>

        1. Navigate to where you want your virtual environment to be created, and then create it with `uv`:

            ```shell
            uv venv VENV_NAME
            ```

            Replace `VENV_NAME` with a name for your virtual environment.

        2. Start the virtual environment:

            ```shell
            source VENV_NAME/bin/activate
            ```

            Your shell's prompt changes to display that you're currently working in a virtual environment:

            ```text
            (VENV_NAME) ➜  portals git:(main) ✗
            ```

        3. To deactivate the virtual environment and return to your regular shell, type `deactivate`.

            When activated, the virtual environment temporarily modifies your `PATH` variable to prioritize packages installed within the virtual environment.
            To avoid conflicts with other projects, it's a good idea to deactivate your virtual environment when you're done working in it.

            To delete the virtual environment, type `rm -rf VENV_NAME`.
            This completely removes the virtual environment directory and its contents.

        </TabItem>
        <TabItem value="Windows" label="Windows">

        1. Navigate to where you want your virtual environment to be created, and create it with `uv`.

            ```shell
            uv venv VENV_NAME
            ```

            Replace `VENV_NAME` with a name for your virtual environment.

        2. Start the virtual environment:

            ```shell
            VENV_NAME\Scripts\activate
            ```

            Your shell's prompt changes to display that you're currently working in a virtual environment:

            ```text
            (VENV_NAME) PS C:/users/username/portals-dir>
            ```

        3. To deactivate the virtual environment and return to your regular shell, type `deactivate`.

            When activated, the virtual environment temporarily modifies your `PATH` variable to prioritize packages installed within the virtual environment.
            To avoid conflicts with other projects, it's a good idea to deactivate your virtual environment when you're done working in it.

            To delete the virtual environment, type `Remove-Item VENV_NAME`.
            This completely removes the virtual environment directory and its contents.

        </TabItem>
        </Tabs>

    </details>

3. In your virtual environment, install Portals:

    ```bash
    uv pip install portals
    ```

    To install a specific version of the Portals package, add the required version to the command, such as `uv pip install portals==1.4.22`.

    <details>
    <summary>Reinstall or upgrade Portals</summary>

    To reinstall Portals and all of its dependencies, run `uv pip install portals --force-reinstall`.

    To upgrade Portals to the latest version, run `uv pip install portals -U`.
    However, the Portals team recommends taking steps to backup your existing installation before you upgrade Portals.
    For more information, see [Prepare to upgrade](/release-notes#prepare-to-upgrade).

    </details>

4. Start Portals:

    ```bash
    uv run portals run
    ```

    It can take a few minutes for Portals to start.

5. To confirm that a local Portals instance is running, navigate to the default Portals URL `http://127.0.0.1:7860`.

6. Create your first flow with the [Quickstart](/get-started-quickstart).

For upgrade information, see the [Release notes](/release-notes).

For information about optional dependency groups and support for custom dependencies to extend Portals OSS functionality, see [Install custom dependencies](/install-custom-dependencies).
