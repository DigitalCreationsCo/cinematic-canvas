## Decentralized Stores & Memory-Safe Asset Management

Last week's update established resilient pipeline error handling with RAI safety interventions. With workflow interruption recovery in place, this week's focus shifted to architectural resilience—the foundation that enables creators to scale without system degradation.

The latest release introduces a decentralized store architecture for the client, polymorphic media reference counting for memory safety, and like/dislike feedback with best-lock semantics. These changes harden the platform against memory leaks, eliminate UI bottlenecks, and give creators explicit control over asset quality prioritization.

The result is a self-recovering creative environment where system state stays synchronized, orphaned assets are automatically garbage collected, and preferred asset versions remain protected during autonomous generation cycles.

### Project Overview

Cinematic Canvas is a generative filmmaking tool that treats storytelling elements as structured primitives—enforcing character persistence, narrative progression, and high-fidelity output across multi-scene workflows. The platform builds structured context for generative video through node-based spatial workflows.

Technology Stack: React, Node.js, PostgreSQL, Google Cloud Platform, Vertex AI, Zustand, React Flow

#### What's New

### Decentralized Store Architecture

The client-side state management has been completely refactored from a monolithic store into specialized Zustand stores with clear separation of concerns. Each domain entity—projects, assets, canvas layout, pipeline state—now owns its state slice independently.

Key architectural improvements include entity-level debouncing to batch rapid UI updates, `ENTITY_UPDATED` event propagation for cross-store synchronization, and memoized selectors for optimized re-render performance. The new store structure eliminates bottlenecks inherent in centralized state trees where unrelated component updates caused cascading re-renders.

![Decentralized Store Architecture](images/2026-03-18-decentralized-stores.png)

### Memory-Safe Asset Management with Reference Counting

Asset lifecycle management now features polymorphic media reference counting with asynchronous cleanup. The system tracks every asset reference across the entire platform—character images, location backgrounds, scene frames—and maintains accurate reference counts in the database.

When entities are deleted or assets are replaced, the system queues orphaned assets for asynchronous garbage collection. This operation runs in a non-blocking background process, ensuring the UI remains responsive even during large-scale cleanup operations. Memory leaks from abandoned assets are eliminated, and storage costs are optimized automatically.

![Asset Reference Counting Architecture](images/2026-03-18-asset-reference-counting.png)
*Reference counting with async cleanup ensures orphaned assets are collected without blocking the creative workflow.*

### Like/Dislike Feedback with Best-Lock Semantics

Creators can now explicitly prioritize preferred asset versions through a like/dislike feedback system. Liked versions acquire "best-lock" status—protected from autonomous override while new generations continue tracking. The system surfaces feedback counts, sentiment rates, and newer-version banners directly in the MetricsPanel.

This enables creators to guide the generation process without manual intervention. When a preferred character expression is found, it remains locked as the canonical version even as the AI generates alternatives. The platform learns from explicit feedback, not just implicit quality metrics.

![Best-Lock Semantics](images/2026-03-18-best-lock.png)
*Best-lock semantics protect preferred versions while allowing new generations to continue in parallel.*

### Node-Based Canvas UI Refinements

The node-based canvas interface received significant polish. Node handles were refactored to unified entry/exit appearance with overflow scrubber styling. The MetadataNodeInspector now features World/Project tabs for entity-level metadata management. Node removal implements soft-delete with confirmation dialogs to prevent accidental data loss.

The Scenes column was added to the TopAssetPanel with 1-second debouncing for undo/redo state persistence. Entity positioning now correctly displays all scenes, characters, and locations on the canvas without overflow clipping. SceneNode components show both start and end frames with edge-to-edge layout for comprehensive visual context.

A high-performance convex EllipsoidMatrix background was implemented for the canvas, replacing static backgrounds with dynamic, perspective-aware rendering that enhances spatial orientation during complex workflows.
