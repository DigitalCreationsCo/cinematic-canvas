## What is Cinematic Canvas?

**Cinematic Canvas** now has a conversational AI collaborator living directly inside the workspace. The new _Chat Sidebar_ opens alongside the existing _Tools Panel_ in mutually exclusive, animated side-by-side drawers — one surface for structured tools, another for freeform conversation.

- **Persistent Message History:** Every message persists across sessions. Close the sidebar, refresh the browser, come back tomorrow — the conversation picks up exactly where it left off. No more lost context.
- **Mutually Exclusive Sidebars with Mount Animations:** The _Tools Panel_ and _Chat Sidebar_ share the same viewport real estate. Opening one gracefully dismisses the other with smooth CSS mount/unmount transitions, keeping the canvas uncluttered.

## 2. tRPC Migration — End-to-End Type Safety

The entire API layer has been rebuilt on tRPC, replacing the previous ts-rest contract system. Every client call, server handler, and validation schema now shares a single TypeScript type — inferred automatically, never hand-written.

- **Zero Runtime Mismatches:** tRPC's router-level inference means the client's `.mutate()` and `.query()` calls are type-checked against the server's exact Zod schemas at build time. If a field is renamed, added, or removed on the server, the client fails to compile — not at runtime in production.
- **`Parameters<T>` for Precise Input Typing:** Complex RPC inputs like `requestFullState` now derive their types directly from handler signatures using `Parameters<T>`, eliminating wrapper types and keeping the contract surface minimal.
- **Zod Validation at the Router Boundary:** Every procedure validates its input against a Zod schema before the handler executes. Invalid payloads return structured error responses immediately — no ad-hoc validation scattered across handlers.

![Diagram showing Client with TypeScript, tRPC Router with Zod validation, and Server Handlers connected by end-to-end type inference](/images/2026-04-24-trpc-migration.png)
*End-to-end type inference: the client, router, and server share a single TypeScript type. Zod validates at the boundary. No hand-authored contracts required.*

**The Result:** An entire class of bugs — mismatched request bodies, stale client types, silent schema drift — is eliminated at compile time. Developer velocity increases because every API change is immediately surfaced across the entire codebase. The migration also reduced the API surface area by ~30%, removing adapter boilerplate that ts-rest required.

## 3. Optimistic Placeholder Nodes

Creating an entity on the canvas used to require a full server round-trip before anything appeared. That latency gap — typically 200–500ms — broke the flow of rapid world-building. Now, entity nodes appear *instantly*.

- **Pending Node Factory:** A new `createPendingNode()` function in _NodeFactory_ generates a fully-rendered placeholder node with an `isPending` flag. The node carries a transient `pendingId` and renders with a subtle pulse animation to signal that confirmation is in flight.
- **Server Echo & Promotion:** When the server persists the entity, it echoes back the `pendingId`. The client's `promotePendingNode()` swaps the placeholder for the authoritative entity node — same position, same dimensions, new data. If the server rejects the creation, the pending node is removed with a fade-out transition.
- **68 New Tests:** Full coverage for `createPendingNode`, `promotePendingNode`, `createEntityWithPendingNode`, and `confirmEntityNode`, including edge cases for duplicate echoes, orphaned pending nodes, and concurrent creation races.

![Timeline diagram showing User Action creating an instant pending node, server processing, then echo confirmation to a finalized entity](/images/2026-04-24-optimistic-ui.png)
*The optimistic creation lifecycle: the canvas responds at 0ms, the server confirms asynchronously, and the pending node is promoted in place.*

**The Result:** Entity creation now feels instant. The perceived latency drops from 200–500ms to 0ms. Creators building worlds with dozens of entities experience a workspace that keeps pace with their thinking — no loading spinners, no jank, no waiting.
